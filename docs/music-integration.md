# 音乐接入

简体中文 | [English](en/music-integration.md)

插件通过 `musicdl_json_v1` JSON 子进程协议调用 Music 项目的搜索与下载能力。Music 保留独立 Python 环境和命令行用法，插件负责会话身份、候选选择、权限、作业、附件及平台投递。

## 配置

Music Service Profile 的私有配置 `home` 指向 Music 项目根目录，`sources` 指定来源顺序，依次支持 `MiguMusicClient`（咪咕）、`KuwoMusicClient`（酷我）、`QQMusicClient`（QQ 音乐）、`NeteaseMusicClient`（网易云音乐）。默认启用已通过完整下载验证的咪咕、酷我；其他来源经过完整搜索和下载验证后再启用。配置中不需要聊天模型、音乐 HTTP 端口或每个人格单独的 Python 解释器。

人格配置 `media.music` 保存 `profileRef`、`enabled` 与 `includeLyrics`，开关均默认 `false`。面板开启音乐能力时同步加入 `bot_music` 与 `music-download`；关闭即时撤销正在执行任务的后续权限，新增权限从下一轮生效。当前任务沿用本轮冻结的歌词偏好。

项目根目录、解释器和输出路径由运营者或宿主确定，不接受模型参数覆盖。首期启用无需额外登录即可通过下载验收的来源。后续来源需要 Cookie 或授权时，接入 Harness credentials，不将凭据保存进人格、候选或工具结果。

## 会话与交付

搜索返回真实候选和宿主生成的候选集标识；下载可以直接按歌名、歌手选择最高匹配，也可依据先前所选候选，不由模型拼接媒体地址。候选、原始音乐、歌词与下载记录属于当前渠道会话。过期候选、跨会话候选以及会话重置后到达的结果均不能继续使用。

歌曲先写入当前作业目录，验证后注册为当前会话附件，作业临时目录结束即清理。`bot_sing action=sing` 接受 `song/artist` 或先前搜索的 `candidateSet/candidate`；当前会话已获取的同曲源音频直接复用。曲库歌曲按混音处理，在下载前检查所选 RVC Profile；分离配置由适配器读取和验证。用户只请求音色转换时，原曲作为输入，不额外登记发送原曲。

合规原生 MP3 直接交付；其他源从原件完整编码一次，默认 192 kbps，并按时长在 160/128/96/64 kbps 中选择可容纳的码率。下载交付与按歌名翻唱的成品均严格小于 20,000,000 字节，最终检查实际大小、完整解码和时长。无法容纳时明确失败，不截断歌曲。显式上传音频转换的 WAV 格式继续按原有音频上限处理。

平台投递复用插件已有附件队列。下载完成、附件登记和平台送达是不同状态；投递失败重试复用已完成的附件，不重新搜索或下载。停止会话、关闭机器人、撤销权限和删除机器人都沿用现有取消及归属清理流程。

## 检查与验收

面板“检查 health”执行 `service.health`，只检查运行环境和协议。来源列表的环境可用状态不代表实际曲目可下载。实际完整下载记录为独立的 `music` 验收；health 绑定 Profile 版本，真实验收同时绑定人格与 Profile 版本。环境检查结果保留检查时间供运营者参考，不因打开面板反复运行外部进程。

验收须包含真实搜索、歧义候选选择、完整歌曲下载及解码、可选歌词、下载后音色转换、停止任务、权限撤销、会话重置和跨会话拒绝。QQ 与微信分别验证适合其格式和体积的发送附件，确认原始歌曲保留且未截短。

## Limitations / Known Issues

音乐源可能改变接口、要求授权、返回试听或拒绝特定曲目，只有实际下载能验证该曲目的可用性。输入音频的本地处理预算为 100 MiB，生成音频支持到 200 MiB；QQ 投递硬上限为 200 MiB，超过直传阈值时分片上传，微信普通附件仍受 20 MiB 限制。本功能的完整 MP3 小于 20,000,000 字节是既定交付策略，与 QQ 软限制独立。音乐能力本身不提供 RVC 模型、人声分离模型或音乐生成。
