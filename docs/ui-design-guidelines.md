# 面板 UI 设计与扩展指导

简体中文 | [English](en/ui-design-guidelines.md)

适用于本插件面板的重构与后续扩展。目标是：沿用现有配置与能力，界面简洁，符合 DSH 的使用习惯，同类操作保持一致。

## 1. 范围与依据

- 配置字段、默认值、权限与持久化以当前源码为准，原型只作为布局和交互参考。
- 不因原型里出现某个控件就新增后端字段，也不因原型省略就删除已有能力。
- 不添加温度、回复风格、人格用途标签、人格简介、任意参考文件管理、工作区保留天数等当前面板没有的配置。
- 保留真实可用的模型推理强度、ASR、视频理解、TTS、STS、音乐、权限、存储管理和主动消息等现有入口；根据条件展示，不为简洁而丢失功能。
- 不复制原型中的示例模型目录、模拟授权、虚构统计、内存保存或假服务状态到正式实现。

本地评审原型位于 `.codex/panel-ui-demo/`，不作为发布依赖。规范与原型冲突时按本规范和真实配置实现。

## 2. 视觉与页面结构

- 保留评审原型的绿色强调色及浅色背景方向，兼顾 DSH 深浅主题。优先使用现有 `--dsw-*` 语义变量；绿色只用于主操作、选中和状态，不覆盖宿主全局配色。
- 使用宿主 React、设置入口与系统字体，不建立第二套应用壳、品牌区或独立主题开关。
- 参考 DSH 的控件尺度：导航宽约 188px、导航项高 40px；内容间距 24px；主标题 20px/28px、字重 500；正文 14px/22px，必要辅助文字 12px/18px。
- 按钮高约 36px，按钮和输入框圆角 12px，内容容器 16px，弹窗 28px。触屏适当增加点击区域；不靠极小字号压缩信息。
- 总览、机器人、人格、服务、自动化保持明确入口。总览只展示真实状态、数量、待处理项和近期活动，不展示服务摘要或快捷操作；服务配置在服务面板管理。
- 机器人和人格采用紧凑列表与详情。新建入口固定在工具栏；名称、渠道和 ID 能区分重名实体。
- 服务采用列表与详情；配置、运行状态和动作在同一上下文。状态必须区分未知、待配置、可用和失败。
- 容器变窄时改为单列或横向分区导航；按插件容器宽度响应，避免宿主导航、插件导航和实体列表同时形成三列固定侧栏。

## 3. 文案

- 默认只显示标题、字段名称、当前值、状态和动作。
- 不添加英文装饰标题、宣传语、页面介绍、重复的“下一轮生效”或解释实现细节的小字。
- 仅在会改变用户决策时保留短提示：输入范围/格式、禁用原因、错误下一步、删除范围。保存生效时机集中显示一次。
- 按钮使用稳定动词：保存、撤销、新建、选择目录、选择文件、打开目录、刷新、启动、停止、删除。
- 成功反馈简短；同一事件不同时堆叠多个提示。错误就近展示，字段错误关联输入框；不把原始异常或内部标识当普通用户文案。
- 删除会话使用紧凑、居中的确认窗口，标题与删除范围说明分开；长会话 ID 换行，不撑满屏幕。删除包含其附件，说明其他会话仍使用的共享附件会保留。
- 中英文同步维护；UI 跟随宿主语言，不改变机器人消息语言或草稿。

## 4. 统一操作契约

统一的是动作含义、提交时机、加载/取消/错误行为，不是让所有按钮使用同一种弹窗。

| 操作 | 点击结果 | 提交与取消 |
| --- | --- | --- |
| 选择目录 | 所有目录字段调用同一原生目录选择入口，成功后回填对应字段 | 只改草稿；取消保持原值；不打开资源管理器、不保存、不启动服务 |
| 选择文件 | 调用系统文件选择器，只接受 JSON 工作流文件 | 与目录选择共用加载、取消、错误和回填流程；只改草稿 |
| 打开目录 | 使用现有宿主能力打开实际目录 | 即时动作，不改字段、不标记未保存 |
| 选择供应商/模型/服务/音色 | 同类选择器使用一致控件；有限选项优先原生 select，复杂目录才使用选择弹窗 | 只改对应草稿；不自动保存、启动、授权、探测或试听 |
| 刷新列表 | 重新读取已有模型、Service Profile 或库扫描结果 | 不覆盖草稿、不要求先保存无关修改；选择项失效时明确显示，不自动选另一个 |
| 检测连接 | 调用该服务已有健康查询能力 | 检测已保存配置，不将目录“已配置”等同于服务“已连接”；不新增仅为展示而存在的探测接口 |
| 保存 | 验证并提交当前编辑范围 | 保存期间防止重复提交；失败保留草稿；成功更新基线 |
| 撤销 | 恢复当前编辑范围的已保存基线 | 不重新请求旧数据覆盖后续编辑；需要确认时只确认一次 |
| 启动/停止/重连/授权 | 调用当前对象对应的已有动作 | 即时执行，仅锁相关操作；已运行服务不伪装成“重新启动” |
| 删除/清理/应用文件 | 明确对象及不可恢复影响后执行 | 使用一次确认；沿用现有清理预览、归属与保护规则 |

### 目录和文件选择

- 当前路径只作为现有能力支持的初始位置；不要为了原生选择器不支持定位而引入新配置或兼容层。
- Windows 目录与文件选择共用置顶所属窗口和取消机制；关闭或取消时一并释放。其他平台的目录选择沿用宿主能力；没有原生文件选择能力时提示不支持，仍可手动填写路径。
- 选择期间显示“选择中…”和取消入口，只锁同一选择动作。其他无关字段仍可编辑。
- 页面切换、对象切换、取消或卸载后，旧选择结果不得回填到新对象。
- 调用失败在字段附近给出简短原因与重试；用户取消不作为错误。
- 手动修改路径、恢复默认或撤销时清除该字段的旧选择错误；保存当前范围时结束其中尚未完成的选择，忽略迟到结果。
- 目录用于工作区、模型库或服务根目录时遵守同一流程。文件选择与打开目录各自保留明确含义。
- 工作流文件使用系统文件选择器并限制为当前支持的 JSON 文件；打开系统文件管理器使用“打开目录”。不新增目录创建、上传或通用文件管理能力。

### 服务与模型选择

- 切换左侧服务列表只是浏览服务配置；机器人设置里的服务选择才是修改配置，不能混用。
- 供应商/模型来自宿主目录；模型变化按现有规则重置不兼容的推理强度，不硬编码示例模型。
- 语音与 STS 选择保留现有 `serviceId/profileId`、能力与就绪状态规则；保留既有必要的工具/技能同步，不新增持久化字段。
- TTS 引擎变化只清理已不兼容的字段；不同引擎的音色不能串用。ASR/视频继续遵循已有主模型关系。
- 小列表直接选择即完成“选择”，随后在页面保存；弹窗选择则在弹窗确认后回填，再由页面保存，不连续弹多个确认。
- 尚未保存的服务配置不能悄悄用于启动。提供一次“保存并启动”，保存失败不启动；不因其他服务的草稿锁住无关动作。
- 保留已有必要联动：Breeze 项目目录选择后，仅在音色目录为空时补全默认目录；服务保存可能触发后台模型发现。页面加载、显式刷新与启动后的健康查询继续按现有契约执行。

## 5. 草稿、保存和反馈

- 按编辑对象和真实后端保存边界维护 `baseline / draft / pending / error`；改回原值即不再 dirty，不引入哈希。
- 同一编辑范围只有一个保存入口，避免同页两个无范围标识的“保存”。工作区、机器人设置等不同提交范围应独立展示或明确命名，不能把多个请求假装成原子保存。
- 普通配置统一先选/改、后保存。启停、授权、撤销信任等命令保留即时操作语义；权限撤销仍在执行时重查。
- 人格切换保留历史，保存后从下一轮生效；在途任务继续使用冻结配置。重构不能改变这些约束。
- 离开有草稿的页面/对象：保存并继续、放弃修改、继续编辑。新建和凭据表单也受保护；凭据只留在当前内存和既有凭据服务中。
- 保存期间若允许继续编辑，合并返回值时不得覆盖提交后输入；否则只冻结当前编辑范围。异步加载以请求/对象身份丢弃迟到结果。
- 写入成功后的刷新失败必须显示为刷新失败，不能报告保存失败或重复提交。
- 首次加载、空列表、加载失败、后台刷新分别处理；加载失败提供局部重试，已有数据刷新失败时保留原数据。

## 6. 配置范围

| 页面 | 允许呈现的已有配置/能力 | 不得自加 |
| --- | --- | --- |
| 模型与回复 | 供应商、模型、支持时的推理强度、处理延时回复及间隔 | 温度、回复风格、人设覆盖项 |
| 媒体 | 当前图片协议、ASR协议、视频理解、TTS引擎/音色/回复模式、STS、音乐等现有设置 | 新协议、新参数、客户端自定义模型路径 |
| 人格 | ID、名称、人设；`persona.md`、`config.json` 的现有打开/应用/导入动作 | 标签、简介、任意参考文件编辑器 |
| 服务 | 当前语音服务地址和目录、Breeze音色目录、图片服务字段、ComfyUI地址/工作流、RVC目录、音乐来源顺序 | ComfyUI项目目录、ComfyUI独立模型下拉、单一音乐来源替代有序数组 |
| 工作区 | 当前目录、存储统计、筛选、预览清理、保留标记等 | 固定“保留30天”等不存在的策略 |
| 自动化 | 当前人格/私聊会话、主动消息已有设置；定时任务内容、执行时间、时区、启停/删除等已有动作 | 任务名称字段、工作日/每周选择器、无对应接口的任务编辑 |

此表限定新增范围，不是删减既有配置的清单。实现前把实际现有字段与提交动作对应到页面；保留配置中已存在但原型未呈现的功能。

## 7. 组件与扩展

- `src/client/index.ts` 留宿主接入、页面切换和必要协调；按页面收拢查询、草稿和动作。复用现有 `ui.ts`、`layout.ts`，只在出现真实重复时提取公共组件。
- 优先统一表单字段、选择器、保存栏、状态反馈、原生 dialog 和异步选择动作，不另建通用工作流框架或第二份状态模型。
- 确认、表单等页面内模态框使用 `<dialog>.showModal()`；保留 Escape、取消、焦点恢复和未保存保护。不要叠加手写焦点陷阱。
- 字段使用原生 form/label/input/select，支持 Enter 提交；提交失败定位首个错误，不在初次显示时标红。
- 样式限于插件根节点，继续使用容器查询、可见焦点和减少动效偏好。宿主适配集中处理，不扩散依赖宿主 DOM 层级的选择器。
- 后续增加入口必须能指出现有 schema/目录/API 依据，并复用对应动作契约。新后端能力需有单独明确的需求，不能作为 UI 美化的附带扩展。

Web 平台实现参考 [Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance/blob/main/skills/modern-web-guidance/SKILL.md)，只取当前改动相关规则；用户对范围与简洁的要求优先。

## 8. 实施顺序与验收

1. 读取本规范、现有源码及工作树；保留其他任务已有修改。先列出现有字段与动作映射，不能照搬原型的模拟实现。
2. 统一目录/文件/服务选择、表单、对话框和保存反馈，再调整页面布局与简洁文案。
3. 修正当前可达的草稿覆盖、离开保护、加载与局部 pending 问题；保留有效的 revision、取消和并发保护。
4. 更新中英文资源与相关测试，执行 [开发指南](development.md) 中 UI 改动要求的类型检查、测试、构建及文档检查。
5. 用真实浏览器确认：目录选择成功/取消/迟到返回；模型与服务选择只改草稿；刷新保留草稿；保存失败/成功后刷新失败；切页保护；键盘、深浅主题、窄宿主容器。

检查前说明具体要防止的失败；通过后不重复跑相同检查。原型或 fake React 测试不证明原生选择器、焦点或真实宿主布局正确。未能实际验证的宿主行为应明确记录。

本方案授权实现与本地验证。推送、发布、安装到运行中的实例、重启真实服务或发送平台消息，仍需用户明确授权。
