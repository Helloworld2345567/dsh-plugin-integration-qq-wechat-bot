# 本地媒体转换性能验证

使用 `python -B tests/benchmark_media_transform.py --repeats 3` 可复现合成素材测试。脚本在项目 `.codex/` 生成素材及输出，退出时清理。测量包含输入探测、编码、合并及成功 GIF 的完整解码校验，不含模型、网络、平台投递或宿主启动 Python 的时间。

本次环境为 Windows、Python 3.13.12、Pillow 12.2.0、FFmpeg 8.1.2。以下为三轮中位数，单位毫秒：

| 场景 | 串行 | 并发 | 加速 |
| --- | ---: | ---: | ---: |
| 单视频：整段编码 / 两路分段 | 3645 | 2299 | 1.59× |
| 两个视频：串行整段 / 两任务各两路分段 | 7252 | 2415 | 3.00× |
| 八张图片：串行 / 四路 | 762 | 210 | 3.63× |

视频素材为 32.25 秒、960×540、24 fps 的 H.264 testsrc2；成品为 480×270、12 fps、128 色、387 帧，整段与分段结果均为 6,468,839 字节，均只编码一轮。分段为 15 + 15 + 2.25 秒，最近一轮流式合并耗时 21 ms，合并阶段只保留一个压缩帧。图片素材为 2048×1536 噪声图，转换为最长宽度 1280 的 WebP，质量 80。

正确性回归另外逐帧比较了非关键帧起点、变帧率视频的整段和分段输出：像素一致，片段边界与尾部时长正确；同时验证体积收敛和四轮后失败行为。运行时并发测试覆盖全局预算、同会话并行、FIFO 排队、撤权、取消和异常释放槽位。

## Limitations / Known Issues

这些数据只代表本机合成素材，不保证其他 CPU、编解码格式、分辨率和系统负载有相同收益。不同场景使用的并发预算分别为 2、4、4 个槽位；表中跨场景的倍数不能直接比较。极长或高细节素材可能需要多轮降质，或无法满足完整时长、最低 12 fps 与 10 MB 上限。
