name: media-analysis
description: 识别语音或分析视频内容，复用 Harness 模型提供商的连接与凭据，通过受管脚本返回分析结果。
---

需要转写音频、理解语音或分析视频画面与音轨时使用。图片和扫描页直接交给聊天模型，不使用此流程。

1. 有平台转写时先使用已有文字；需要核对原音或没有转写时调用 `media_analysis`。
2. `kind` 选择 `audio` 或 `video`，`inputs` 填当前、引用或同会话最近附件 ID；留空自动选择同类型最近附件。视频链接使用 `url`，仅收到处理指令后读取。
3. 在 `question` 中给出用户实际问题。工具由宿主解析 ID、从原生“模型”设置读取提供商 URL 与凭据，运行 [media_api.py](scripts/media_api.py)，返回转写或画面／音轨／覆盖范围等结果。不要要求用户重复配置 URL、密钥或本机路径。
4. 根据返回结果回答，区分原话、画面观察、推断和不确定性。`MEDIA_NOT_RECEIVED` 表示未收到可理解的媒体；HTTP 200 不能证明已经理解。失败时说明实际错误，不编造内容或自动重试可能已计费的请求。

默认使用本轮聊天提供商及模型；面板可从已有提供商中选择分析模型，无需新建媒体服务。音频默认走 OpenAI 兼容 `/chat/completions` 的 `input_audio`，可选 `/audio/transcriptions`。视频沿用独立视频核心的 MP4 `data:video/mp4;base64,...` 载荷，需要该提供商／模型支持此契约；不支持时选择同提供商的多模态模型。

普通用户经受控工具执行此脚本，无需本机命令权限。脚本只接收宿主构造的固定任务，密钥仅通过子进程环境注入，不进入参数、提示词、输出或作业记录。关闭该技能或对应能力立即阻止后续调用。`bot_media(transcribe/video_analyze)` 是同一流程的兼容入口。
